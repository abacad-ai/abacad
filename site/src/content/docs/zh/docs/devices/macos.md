macOS 自带一个兼容 VNC 的服务器（屏幕共享）。abacad 可以用两种方式登录，区别很重要：

| 登录方式 | RFB 类型 | 你得到什么 |
| --- | --- | --- |
| **macOS 账户**（推荐） | 30（Apple DH） | 已登录用户的 console 会话。键盘和鼠标能到桌面，也能到锁屏。 |
| VNC 密码 | 2（经典 DES） | 没有用户身份的会话。在现在的 macOS 上常常落到 `loginwindow`，所以画面可能显示用户登录时的登录界面，并且不响应输入。 |

本文用 **macOS 账户** 方式。

## 打开屏幕共享

1. **系统设置 → 通用 → 共享 → 屏幕共享**，打开。
2. 点屏幕共享旁边的 **ⓘ** → **电脑设置**。**VNC 查看程序可以使用密码控制屏幕** 对 abacad
   是可选的；它只增加旧的 type 2 路径，可以不开。
3. 确认账户有控制屏幕的权限。普通的屏幕共享通常是所有用户。
4. 确认 Mac 防火墙允许屏幕共享（系统设置 → 网络 → 防火墙 → 选项）。

服务监听 TCP **5900**。

## 添加到 hub

在控制台点 **添加设备**：

- **名称：** `Mac mini`
- **Host：** Mac 的 IP，例如 `192.168.1.92`
- **端口：** `5900`
- **登录方式：** **macOS 账户**
- **macOS 用户名：** 短名（`whoami`），不是显示名
- **密码：** 你登录 Mac 用的密码，不是 VNC 密码
- **平台：** macOS
- **模式：** `gateway`

保存后选中这台机器。如果卡片显示
`macOS: switch Sign-in to "macOS account"`，说明它还在用旧的 VNC 密码方式；编辑并切换。

## 为什么 VNC 密码不够

Apple 的屏幕共享服务接受三类认证：

- **type 30（Apple DH）** —— 真实的 macOS 账户名和密码，用 Diffie-Hellman 交换，AES-128-ECB
  加密。服务器知道 **是哪个用户** 在连接，所以能把会话附着到该用户的 console。
- **type 33/35/36** —— Apple 的 RSA tunnel 及其变体，noVNC-ARD 使用。abacad 用 type 30，
  因为它是可互操作方案里最简单的。
- **type 2（经典 VNC）** —— 一个整机密码，没有用户名。

type 2 没有身份可以附着。在现在的 macOS 上它可能落到 `loginwindow` 会话；那是一个真实
存在的独立会话，会一直渲染最后一次登录界面。症状很容易误读：

- 画面显示登录界面，时钟往往停在用户登录的时刻；
- Mac 能 ping 通，TCP 5900 也接受连接；
- 点击和输入看起来没反应，因为它们去了不活跃的 `loginwindow`，不是用户的桌面。

这不是显示器睡眠，也不是 hub 丢了按键。是认证路径选错了会话。

## 如果 Mac 锁屏了

hub 已经用账户登录了，所以连接附着在正确的会话上。macOS 锁屏仍然要账户密码才会解锁：

1. 在画面里点一下（或按 **空格**）显示密码框。
2. 输入 macOS 账户密码，回车。
3. 如果键盘没反应，点查看器顶部的 **Keyboard**，用 noVNC 的屏幕键盘。

锁屏是安全输入界面；有些 macOS 版本只在 ARD 会话建立后才接受合成事件，而 type 30 就是
在做这件事。

## 如果屏幕真的睡了

画面冻住也可能是 Mac 显示器睡眠。Mac 能 ping 通、能接受 TCP 5900，但 framebuffer 停在
最后一帧。只在确认设备使用 **macOS 账户** 登录后再检查这一点。

物理唤醒它，或用 Apple 的屏幕共享 App 连一下，然后重连。让无头 Mac 保持唤醒：

```bash
# 系统不睡、显示器不睡；magic packet 唤醒。
sudo pmset -a sleep 0 displaysleep 0 womp 1
```

或者在需要可用时运行 `caffeinate -d -s`。台式机也可以在系统设置 → **能源** 里打开
**显示器关闭时防止自动睡眠**。

## 屏幕共享 vs 远程管理

如果开了 **远程管理**，它拥有登录窗口和自己的访问列表。type 30 仍然可能工作，但账户必须
在 **允许访问** 列表里，并有 Observe/Control 权限。如果认证报
`Authentication or authorization failure`，说明 DH 交换已经成功、Mac 拒绝了账户 —— 检查
远程管理的访问列表，而不是密码。

简单配置建议：

- 开 **屏幕共享**，关 **远程管理**；
- 使用的 macOS 账户是管理员，或被允许控制屏幕；
- 旧的 VNC 密码复选框可以不开。

从远程管理切到屏幕共享是配置变更，不是 workaround：它把 Apple 托管的登录会话从路径里
拿掉。

## 保持可达

- 防止睡眠：**系统设置 → 能源 → 显示器关闭时防止自动睡眠**，或者在 hub 需要时运行
  `caffeinate -s`。
- 如果 Mac 用 Wi-Fi，给它一个 DHCP 保留地址，host 字段才不会失效。
- 在防火墙里把 TCP 5900 限制为只允许 hub 的 IP。整个网络里只有 hub 需要访问它。

## 已知问题

- type 30 用 4096 位素数。第一次连接会比 VNC 密码方式慢一点，这是正常的。
- hub 把 macOS 账户密码保存在 `config.yaml`（权限 `0600`）。如果不能接受，创建一个专门
  用于远程控制的本地 macOS 账户。信任模型和保存 VNC 密码一样，只是这个凭据能力更强。
- 重启后屏幕共享可能显示登录窗口。那是 `loginwindow` 会话，type 30 仍然是登录正确账户的
  方式。
- 根据 macOS 版本和共享设置，可能只接受一个或少数几个查看者。如果 agent 和浏览器冲突，
  一次用一个。
- Apple 自己的屏幕共享 App 在连另一台 Mac 时优先用 Apple 协议。从 abacad 连，请用
  浏览器/noVNC 路径或标准 VNC 客户端；认证之后它们都是普通 RFB。

在把 hub 暴露到局域网之外以前，先读 [安全](/zh/docs/operations/security/)。
